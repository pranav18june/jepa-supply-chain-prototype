## Design decision

Primary engineering path: a numerical-state EMA latent predictor with auxiliary state/cost supervision, compared with an independent LeWM-inspired shared-encoder SIGReg variant and the same model without latent loss. This is a **hybrid supervised JEPA adaptation**, not faithful V-JEPA 2 or LeWM reproduction. Both variants start from scratch; visual weights cannot be treated as numerical supply-chain encoders. SIGReg implementation attribution and MIT license accompany `src/models/controlled.py` in LEWM_LICENSE. The state encoder has no graph message passing or variable-topology transfer; these claims are excluded.

CEM searches bounded dispatch requests. The unchanged physical simulator projects requests through available stock, routing and greedy edge packing. Source procurement and intermediate warehouse rules stay native; arbitrary order/routing/expediting control is not implemented. See ARCHITECTURE.md for the precise restricted action contract.

## round_claude addendum (2026-10-17)

### Corrections to the audit above (verified in local source)

- **V-JEPA 2-AC target handling.** In `vjepa2-main/app/vjepa_droid/train.py`, the action-conditioned stage computes both predictor context and targets with a *frozen* pretrained encoder (`target_encoder` copied from the encoder, `requires_grad=False`, no EMA update in this stage, `forward_target` under `no_grad`), and trains only the predictor with `loss_exp`-power (L1 in released configs) teacher-forced loss plus an autoregressive rollout loss (`auto_steps`). EMA targets belong to the stage-1 masked video JEPA. Our `ema` variant is therefore a stage-1-style EMA-target objective trained jointly with actions, not a V-JEPA 2-AC reproduction; the closest analogue of "representation trained without physical labels, predictor in latent space" is our `jepa_only` variant (latent + SIGReg, decoder fitted on detached latents).
- **Earlier ISOMORPH pairing claim.** The legacy adapter's paired probes were exact for one step only: source lead-time draws are consumed sequentially and policy-dependently (`self.rng.normalvariate`, 1 vs 111 draws over 48 days for native vs uniform-random). `DecisionEnv` keys these draws by (day,node,item). Demand was already action-independent.
- **Last-mile capacity sizing.** The upstream builder sizes the two last-mile lanes from the realized horizon-mean λ of all 50 items; the 3-item adapter keeps that capacity. It binds at large requests (14% of v3d training steps saturate a lane). It is now exposed as observed metadata to every controller (see PROBLEM_FORMULATION.md).

Decision: test persistence, ridge, direct-delta MLP (+ensemble), and one latent architecture under four objectives with matched decoder targets, plus the known-mechanics hybrid and an exact-simulator oracle as references. Rejected for now with reasons: MBPO/Dreamer/TD-MPC2 (finite-horizon MPC question does not need value learning; would confound H1/H3), graph models (fixed topology; no transfer claim possible), OR-Gym (ISOMORPH with `DecisionEnv` now gives exact paired interventions, capacity interaction and multi-echelon replenishment; OR-Gym would add procurement control but was not needed to answer H1–H4 on this narrower action).
